# English, Spanish and French

`next-intl` supplies App Router locale segments and locale-specific messages. English is default. `/network?query=Atlas` redirects to `/en/network?query=Atlas`; translated equivalents are `/es/network` and `/fr/network`.

EN / ES / FR changes the prefix while preserving path/query/fragment. Selection lives in the URL, not an identity cookie. APIs and dotted public resources bypass locale middleware.

## Stable machine surfaces

`/api/v1/*`, `/api/frame`, `/api/mcp`, `/.well-known/agent-card.json`, `/llms.txt`, `/robots.txt`, `/sitemap.xml` and `/icon.svg` are unchanged. Human developer explanations are translated; JSON fields, capability IDs/enums, error codes, tool and provider names are not.

UI `/api/frame` accepts optional validated `locale: en|es|fr`. This affects human-readable decomposition only. Groq receives a language preference, never authority over budget or capability rules. Fallback preserves IDs/dependencies and localizes titles, purposes and rationale. REST/MCP stays English by default. User objectives and verbatim evidence retain their source language; translated text is never presented as an original quotation.

## Maintaining copy

Reviewed triples are in `apps/signalforge/messages/*-copy.ts` and `translations.ts`. UI uses `useCopy()` or async server `getCopy()`. Only the current locale dictionary is sent to the client. Source-text hashes are internal keys. Unknown external text remains verbatim; add all controlled UI strings in three languages before release.

Tests cover nonempty entries, hash collisions, fallback capability mapping, locale routes, selection/query preservation, metadata and protocol URLs. Check French text at mobile widths. Canonical/hreflang and x-default metadata cover public pages; session route details are noindex and excluded from the sitemap.
